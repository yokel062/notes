来源：python/zeus_examples/GEMM/minitile_vcs_perf_baseline.md，VCS + trace + profiler 提取 PE union。

MR !278 9/9 PASS PE union 1.57x geomean wall 只在 PE-bound 上显著下降

汇报口径

  • 这次优化不改变数值语义，主要影响 RTL 上 PE 执行单元的排布和忙碌时间。
  • PE-bound 稠密 GEMM 收益最大：dense bf16 128x512x512 wall 下降 25%，blocked fp8 12x8192x128 wall 下降 34%。
  • 非 PE-bound 或 decode 场景中，PE 变快后瓶颈转移到 DT / setup / 数据搬运，wall 变化不一定明显。

DSA Indexer K 2core 算子更新支持

目标算子：python/zeus_examples/VP/test_dsa_indexer_k_prep_store_2core_kernel.py。

MR !380 MR !407 2core owner-routed scatter

MR !380：绕开 rsqrt broadcast 问题

  • 为 DSA Indexer K 2core 打开 body cache dump，使用 wgt_ptr:inout 验证 owner-routed weight-bank scatter。
  • LayerNorm variance scale 改为 runtime scalar division，避开 VP Sqr/Smt 路径里 [T,1] 与 [1,T] 的错误 broadcast。
  • raw fp8 dump 从逐字节比较改为 fp8 decode 后数值比较，避免 fp8 bucket 边界 rounding 造成误判。
  • 原失败 dump fp8 cosine 约 0.949，workaround 后 fp8 cosine 约 0.999973，只剩边界字节差异。

MR !407：支持 H 维 tiled reduction

  • 扩展双核 DSA prep/store VP kernel 的 H 维累加能力，支持 hidden reduction 按 H 维切 tile。
  • 新增/扩展 sim range 和 VP passed-test registry，覆盖 H=3072 与 H=4096。
  • fp8 body-cache raw compare 对 H-tiled fp32 accumulation 更敏感，因此把 relaxed fp8 raw cosine threshold 限定到 golden_dsa_indexer_k_prep_store。
  • H=4096 的 fp8 body-cache raw compare cosine 约 0.999883，scale_cache 基本保持一致。

这块可以作为 DSA 算子支持进展汇报：!380 先把 2core owner-routed scatter 和 rsqrt/broadcast 问题跑通； !407 再把 H 维从固定整块扩展到 tiled reduction，覆盖更大的 hidden size。

InjectSync 重构/修复相关任务

两项 MR 都围绕真实 VCS 暴露出的指令依赖缺口，把同步注入从“看起来有依赖”推进到更贴近物理读写关系。

MR !352 MR !389 merged

MR !352：DMA RMW + VP same-unit RAW

  • 修正 Phase 4 dmaRawConflicts 判定：从比较 GDG descriptor BReg，改为比较真实 DRAM baseAddr。
  • 解决两个方向的错误：vector_add descriptor 复用导致误报，sgl_moe writers_scratch 同 base 不同 descriptor 导致漏报。
  • 重做 VP same-unit static-L2 RAW：去掉过粗的 hasUnitOpBetween 跳过逻辑，精确识别同静态 L2 base 的 VP 读写。
  • 验证覆盖 MLIR、sgl_moe sim、add/log VCS race 修复，并确认 PE GEMM 不被破坏。

MR !389：PE accumulator dst read 建模

  • 将 PEComputeOp.dst 同时建模为 read buffer，因为 f32acc 路径会把 dst 作为 accumulator 读改写。
  • 闭合 DT/VP 初始化 accumulator 到 PE 开始计算之间的 RAW 依赖，避免 RTL 上 PE 先于初始化完成启动。
  • 对应修复原 f32acc GEMM VCS failure：M=128 K=128 N=128 和 M=207 K=377 N=340 均 VCS PASS。
  • 风险处理采用保守同步：纯覆盖写 PE case 可能多插安全 mail，但 token 配平保持正确，优先保证正确性。

这部分可以作为周会里的“同步注入重构闭环”：!352 处理 DMA/VP 依赖识别，!389 补 PE accumulator 的真实读依赖； 两者共同把 func serial 掩盖、VCS 才暴露的 race 收敛到可验证的同步规则。

VCS 失败定位：把问题拆成独立线

本周定位重点是避免把所有 GEMM VCS failure 混成一个回归，按 VCS A/B、真实 staged bytes、case differential 收敛责任层。

blocked_aligned padding 已闭环 f32acc 独立归因 VCS 证据优先

blocked_aligned GEMM

  • 根因确认在 VCS framework 的 weight layout staging：BlockedLayout 只产 compact bytes，padding 只在 write_to_file 路径补齐。
  • 消费侧绕过 write_to_file 直接取 hw_data.tobytes，导致每个 weight block 漏 16KB padding。
  • compiler/kernel 按 padded layout 寻址，VCS 实际灌入 compact layout，multi-block 后发生错位。
  • 修复方向是让 framework 复用 sim_check layout，并让消费侧走 padded write_to_file / byo_weights 通道。

f32 accumulator GEMM

  • 通过 bf16acc vs f32acc 对照，把问题从 blocked_aligned padding、piggyback/truncf 等候选里拆出来。
  • f32acc 属于累加器路径上的独立问题，不应复用 blocked_aligned 的 weight padding 解释。
  • 后续已把 f32acc active case 纳入 VCS 状态页，便于持续跟踪当前 master 的回归状态。

方法论沉淀：func PASS 和静态分析自洽不能直接豁免 compiler 或 framework。VCS-only 问题优先下载 artifact， 量真实 input / weight / golden / raw output 字节，再做最小 A/B。
