Merged UScale 不是一块可以任意摆放的 scratch

硬件确实允许 Weight 与 UScale 使用不同地址，但我们的第一阶段目标不是开放“任意 USaddr”。我们希望保留 每个 BLOCK_K weight block 与自己的 merged UScale 紧邻 的布局，让 PE 在近存计算的关键路径上尽量连续取数。

✓

希望先对齐的契约：weight 按 block 划分，每个 BLOCK_N × BLOCK_K weight block 后面紧跟同编号的 merged UScale。另一份只读 original weight UScale 可以独立连续存放，因为它只参与更新，不在 PE MAC 的直接取数关键路径上。

核心分歧不是“硬件能不能”，而是“编译器承诺什么布局”

!

这里表达的是必须先保留的性能契约，不是已经完成的性能定量结论。Zeus PE 直连 Weight LDG，weight 与 UScale 的距离会影响 DRAM row/cache locality；“任意摆放”的实际退化幅度仍需要同一 kernel、同一 dynamic 的 VCS A/B 验证。在完成这项验证前，不应把任意 USaddr 当成没有性能代价的等价布局。

希望先和 Issue owner 对齐的三件事

01 · BLOCK

weight 按 BLOCK_K 划分

每个 block 是一块 weight，并和同编号的 merged UScale 组成 combined unit。

02 · PLACEMENT

merged scale 固定紧跟 weight

original scale 可以独立连续放置，merged scale 不接受任意 placement。

03 · OWNERSHIP

buffer ownership 由调用方负责

双缓冲、并发 slot 与 graph 生命周期属于 torch_zeus/operator 层契约。
