方案一：原地更新与 Weight 紧邻的 Fused UScale

当前 kernel 只提供方案一：每个 BLOCK_N × BLOCK_K weight block 后保留固定的 Fused UScale 槽，设备侧计算后原地覆盖该槽。ABI 不增加独立 Fused UScale 指针，也不开放任意 USaddr。方案二——Weight 与 Fused UScale 任意分离——暂不提供。

✓

当前已实现的契约：weight 按 block 划分，每个 BLOCK_N × BLOCK_K weight block 后面紧跟同编号的 writable Fused UScale。另一份只读 original weight UScale 可以独立连续存放，因为它只参与更新，不在 PE MAC 的直接取数关键路径上。

方案一 · 已提供 原地更新 Fused UScale 无额外 fused_uscale_ptr 方案二 · 暂不提供

下面内嵌本页对应的标准 GEMM example。关键 ABI 是 activation_scale_ptr、指向 LDG combined units 的 packed_weight_ptr_list，以及只读 origin_uscale_ptr_list；计算结果直接写回 packed weight 后面的相邻 Fused UScale 槽。

gemm_normal_blocked_aligned_fp8xfp8_ugroup128_fused_uscale_bf16dst_f32acc_1x1024x128_1core.py 

# SIM_PARAMS: activation_fp8:ptr:in:[1,1,"M","K"]:fp8  activation_scale:ptr:in:[1,"M","K//128","N"]:bf16  packed_weight:wgt_ptr:inout:[1,"N","K"]:fp8:uscale_128_aligned_147456_bk_1024_bn_128  origin_uscale:wgt_ptr:in:["N//128","(K+1023)//1024",8,1024]:bf16:raw  output:ptr:out:[1,1,"M","N"]:bf16  M:i32  K:i32  N:i32
# SIM_GOLDEN: fused_uscale_matmul
# SIM_RANGE: M=1:3 K=1024:3072 N=128:384
"""使用外部 activation scale 在设备侧融合 UScale 的标准 FP8 GEMM。

ABI 约定：

* ``activation_fp8_ptr``：GDG，只读，逻辑 shape 为 ``[M, K]``。
* ``activation_scale_ptr``：GDG，只读。activation 沿 K 维按 ``UGROUP``
  做 per-group 量化，原始逻辑 scale shape 为 ``[M, K / UGROUP]``；当前 ABI
  要求 host 沿 N 维展开后传入 ``[M, K / UGROUP, N]``，使每个输出通道都能
  直接与自己的 original weight UScale 相乘。kernel 要求 activation 与 weight
  使用相同的 ``UGROUP``；ABI 用该参数表达量化粒度，本 example 取 128。
* ``packed_weight_ptr_list``：GDG 中的 ``[CORE_NUM]`` 个 i64 地址；每个地址
  指向本 core 的 LDG inout 区域。LDG 按 ``n_block``、``k_block`` 排列，每个
  combined unit 为 ``[BLOCK_N x BLOCK_K FP8 weight][一个物理 WUS page]``。
  一个物理 WUS page 固定包含 8 个 WL1 lane，每个 lane 的 stride 为 1024 个
  BF16，因此容量为 ``8 x 1024 x 2 bytes = 16 KiB``；这是当前硬件布局的固定
  page 容量，不是逻辑 UScale 的大小。逻辑有效数据只有
  ``BLOCK_N x (BLOCK_K / UGROUP)`` 个 BF16，其余位置是页内 padding。
* ``origin_uscale_ptr_list``：GDG 中的 ``[CORE_NUM]`` 个 i64 地址；每个地址
  指向本 core 的只读 LDG。它按同样的 block 顺序保存 original weight UScale，
  每个 block 的逻辑 shape 为 ``[BLOCK_N, BLOCK_K / UGROUP]``，转换后的物理
  WUS page 为 ``[8 WL1, 1024 BF16]``。令
  ``G = BLOCK_K / UGROUP``、``R = BLOCK_N / 8``，页内排列为：

  ``logical[BLOCK_N, G]``::

      N channel 0          [group 0, group 1, ..., group G-1]
      N channel 1          [group 0, group 1, ..., group G-1]
      ...
      N channel BLOCK_N-1  [group 0, group 1, ..., group G-1]

  ``physical[8 WL1, 1024 BF16]``::

      WL1 0: [group 0: N 0..R-1][group 1: N 0..R-1]...[padding]
      WL1 1: [group 0: N R..2R-1][group 1: N R..2R-1]...[padding]
      ...
      WL1 7: [group 0: N 7R..8R-1][group 1: N 7R..8R-1]...[padding]
* ``output_ptr``：GDG，写出逻辑 shape ``[M, N]`` 的 BF16 结果。

``M`` 是运行时维度，kernel 以 ``BLOCK_M=1`` 逐行执行；``K`` 必须按
``UGROUP`` 对齐，每个 core 的 ``N`` 必须按 ``BLOCK_N`` 对齐，``BLOCK_K``
可以包含多个 ``UGROUP`` quant group。
同一份 ``packed_weight`` 不能被多个
invocation 并发更新，kernel 返回时其中保留最后一行对应的 fused UScale。
"""

import triton
import triton.language as tl


@triton.jit
def gemm_fused_uscale_fp8xfp8_kernel(
    activation_fp8_ptr,           # GDG readonly；FP8 [M, K]
    activation_scale_ptr,         # GDG readonly；BF16 per-group scale [M, K / UGROUP, N]
    packed_weight_ptr_list,       # GDG [CORE_NUM] 地址表 -> LDG inout [weight block][物理 WUS page]
    origin_uscale_ptr_list,       # GDG [CORE_NUM] 地址表 -> LDG readonly；每个 block 逻辑 [BLOCK_N, BLOCK_K / UGROUP]，物理 WUS page [8, 1024]
    output_ptr,                   # GDG writeonly；BF16 [M, N]
    M,                            # 运行时 i32 标量；GEMM M
    K,                            # 运行时 i32 标量；GEMM K
    N,                            # 运行时 i32 标量；GEMM N
    CORE_NUM: tl.constexpr,       # 编译期标量；PE core 数
    BLOCK_M: tl.constexpr,        # 编译期 M tile；当前只支持 1
    BLOCK_K: tl.constexpr,        # 编译期 K tile；必须是 UGROUP 的整数倍
    BLOCK_N: tl.constexpr,        # 编译期 N tile；packed weight block 的 N 维
    UGROUP: tl.constexpr,         # 编译期标量；activation/weight 沿 K 的量化粒度
):
    """逐 activation row 更新相邻 fused UScale，再执行 block GEMM。"""
    # 物理 WUS 页由 8 个 WL1 lane 组成，每个 lane 固定占 1024 个 BF16。
    # 一个 BLOCK_N tile 均分给 8 个 lane，每个 lane 承载 BLOCK_N / 8 个
    # 不同输出通道的 scale。
    USCALE_ELEMENT_BYTES: tl.constexpr = 2
    USCALE_LANES: tl.constexpr = 8
    USCALE_LANE_STRIDE_BF16: tl.constexpr = 1024
    USCALE_ROWS_PER_LANE: tl.constexpr = BLOCK_N // USCALE_LANES
    USCALE_PAGE_BF16_ELEMS: tl.constexpr = (
        USCALE_LANES * USCALE_LANE_STRIDE_BF16
    )
    GROUPS_PER_WEIGHT_BLOCK: tl.constexpr = BLOCK_K // UGROUP
    WEIGHT_BYTES_PER_BLOCK: tl.constexpr = BLOCK_N * BLOCK_K
    ALIGNED_SPACE_BYTES: tl.constexpr = (
        WEIGHT_BYTES_PER_BLOCK
        + USCALE_PAGE_BF16_ELEMS * USCALE_ELEMENT_BYTES
    )

    # BLOCK_M 必须为 1：不同 activation row 有不同的 scale，而一次 PE dot
    # 只能为整个 M tile 绑定同一份 weight UScale。
    tl.static_assert(BLOCK_M == 1, "每次 dot 只能消费一行 activation scale")
    # BLOCK_K 是 PE tile 宽度，不等于 quant group。一个 weight block 可以
    # 包含多个 UGROUP；只要求 group 完整落在 block 内，并且全部 scale
    # 能放进每个 WL1 lane 的物理区域。
    tl.static_assert(BLOCK_K % UGROUP == 0, "K block 必须包含整数个 quant group")
    tl.static_assert(
        BLOCK_N % USCALE_LANES == 0,
        "输出通道必须能够均分到 8 个 WL1 lane",
    )
    tl.static_assert(
        GROUPS_PER_WEIGHT_BLOCK * USCALE_ROWS_PER_LANE
        <= USCALE_LANE_STRIDE_BF16,
        "每个 WL1 lane 的 quant-group scale 必须能放入自己的 WUS 区域",
    )

    core_id = tl.program_id(axis=0)
    n_per_core = N // CORE_NUM
    total_m_blocks = tl.cdiv(M, BLOCK_M)
    total_n_blocks = tl.cdiv(n_per_core, BLOCK_N)
    total_k_blocks = tl.cdiv(K, BLOCK_K)
    total_k_groups = tl.cdiv(K, UGROUP)

    # 两个 ptr_list 自身位于 GDG；表项分别给出本 core 的可写 packed LDG
    # 和只读 original-USScale LDG 基地址。
    packed_weight_addr = tl.load(packed_weight_ptr_list + core_id)
    packed_slab_base = packed_weight_addr.to(tl.pointer_type(tl.bfloat16))
    packed_weight_base = packed_weight_addr.to(
        tl.pointer_type(tl.float8e4nv)
    )
    origin_uscale_addr = tl.load(origin_uscale_ptr_list + core_id)
    origin_uscale_base = origin_uscale_addr.to(
        tl.pointer_type(tl.bfloat16)
    )

    activation_template = tl.make_block_ptr(
        base=activation_fp8_ptr,
        shape=(M, K),
        strides=(K, 1),
        offsets=(0, 0),
        block_shape=(BLOCK_M, BLOCK_K),
        order=(1, 0),
    )
    output_template = tl.make_block_ptr(
        base=output_ptr,
        shape=(M, CORE_NUM, n_per_core),
        strides=(N, n_per_core, 1),
        offsets=(0, core_id, 0),
        block_shape=(BLOCK_M, 1, BLOCK_N),
        order=(2, 1, 0),
    )

    lane_values = tl.arange(0, USCALE_ROWS_PER_LANE)
    fused_uscale_offset = WEIGHT_BYTES_PER_BLOCK // USCALE_ELEMENT_BYTES
    total_weight_blocks = total_n_blocks * total_k_blocks
    total_scale_segments = (
        total_weight_blocks * USCALE_LANES * GROUPS_PER_WEIGHT_BLOCK
    )

    # BLOCK_M 固定为 1，但 M 是任意运行时维度。每一行必须先完成自己的
    # fused-USScale 更新和 GEMM，才能让下一行安全复用同一批 LDG scale 槽。
    for m_block in range(total_m_blocks):
        m_start = m_block * BLOCK_M

        # 把 [weight block, 8 WL1 lane, K-group] 展平成一个循环，保证
        # 当前行的全部 fused UScale 写回发生在任何 weight load 之前。
        # 每个 segment 处理一个 lane 内连续的 BLOCK_N / 8 个 N-channel scale。
        for scale_segment_idx in range(total_scale_segments):
            segments_per_block = USCALE_LANES * GROUPS_PER_WEIGHT_BLOCK
            block_idx = scale_segment_idx // segments_per_block
            segment_in_block = scale_segment_idx % segments_per_block
            lane = segment_in_block // GROUPS_PER_WEIGHT_BLOCK
            group_in_block = segment_in_block % GROUPS_PER_WEIGHT_BLOCK
            n_block = block_idx // total_k_blocks
            k_block = block_idx % total_k_blocks
            global_k_group = (
                k_block * GROUPS_PER_WEIGHT_BLOCK + group_in_block
            )
            n_start = n_block * BLOCK_N
            global_n_start = core_id * n_per_core + n_start
            lane_offset = (
                lane * USCALE_LANE_STRIDE_BF16
                + group_in_block * USCALE_ROWS_PER_LANE
            )
            n_lane_offset = (
                global_n_start + lane * USCALE_ROWS_PER_LANE + lane_values
            )
            packed_block_byte_offset = block_idx * ALIGNED_SPACE_BYTES
            packed_block_bf16_offset = (
                packed_block_byte_offset // USCALE_ELEMENT_BYTES
            )
            origin_page_offset = block_idx * USCALE_PAGE_BF16_ELEMS

            # fused UScale = original weight UScale * activation scale。
            # 一个 WUS 物理页服务 8 个 WL1，所以每个 K-group 都必须执行
            # 8 次 lane 读写；每个 lane 处理不同的 BLOCK_N / 8 个输出通道。
            # 页内有效布局为 [8 WL1, BLOCK_K / UGROUP K-groups,
            # BLOCK_N / 8 N-channels]，不是复制相同数值。
            original_uscale = tl.load(
                origin_uscale_base
                + origin_page_offset
                + lane_offset
                + lane_values,
                memory_type="weight",
            ).to(tl.float32)
            # host 已把当前 M 行、当前全局 K-group 的 act scale 沿 N 展开，
            # 因而当前 WL1 lane 能用一次 GDG 向量 load 取到
            # BLOCK_N / 8 个值。
            activation_scale = tl.load(
                activation_scale_ptr
                + (m_start * total_k_groups + global_k_group) * N
                + n_lane_offset,
                mask=global_k_group < total_k_groups,
                other=0.0,
            ).to(tl.float32)
            fused_uscale = (
                original_uscale * activation_scale
            ).to(tl.bfloat16)
            tl.store(
                packed_slab_base
                + packed_block_bf16_offset
                + fused_uscale_offset
                + lane_offset
                + lane_values,
                fused_uscale,
                memory_type="weight",
            )

        # 当前行的 scale 更新结束后走标准 blocked GEMM。weight load 使用
        # 既有 WUS 路径读取相邻 fused UScale；tl.dot 本身不新增 scale 参数。
        for n_block in range(total_n_blocks):
            n_start = n_block * BLOCK_N
            accumulator = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

            for k_block in range(total_k_blocks):
                k_start = k_block * BLOCK_K
                block_idx = n_block * total_k_blocks + k_block

                activation = tl.load(
                    tl.advance(activation_template, (m_start, k_start)),
                    boundary_check=(0, 1),
                    padding_option="zero",
                )
                packed_block_byte_offset = block_idx * ALIGNED_SPACE_BYTES
                weight = tl.load(
                    tl.make_block_ptr(
                        base=packed_weight_base + packed_block_byte_offset,
                        shape=(BLOCK_N, BLOCK_K),
                        strides=(BLOCK_K, 1),
                        offsets=(0, 0),
                        block_shape=(BLOCK_N, BLOCK_K),
                        order=(1, 0),
                    ),
                    memory_type="weight",
                    ugroup=UGROUP,
                )
                accumulator += tl.dot(
                    activation,
                    tl.trans(weight),
                    out_dtype=tl.float32,
                )

            tl.store(
                tl.advance(output_template, (m_start, 0, n_start)),
                tl.expand_dims(accumulator.to(tl.bfloat16), 1),
                boundary_check=(0, 2),
            )


signature = {
    "activation_fp8_ptr": "*fp8e4nv",
    "activation_scale_ptr": "*bf16",
    "packed_weight_ptr_list": "*i64",
    "origin_uscale_ptr_list": "*i64",
    "output_ptr": "*bf16",
    "M": "i32",
    "K": "i32",
    "N": "i32",
}

constants = {
    "CORE_NUM": 1,
    "BLOCK_M": 1,
    "BLOCK_K": 1024,
    "BLOCK_N": 128,
    "UGROUP": 128,
}


if __name__ == "__main__":
    from kernel_to_linalg import kernel_to_linalg

    kernel_to_linalg(
        gemm_fused_uscale_fp8xfp8_kernel,
        signature,
        constants,
        True,
    )
!

方案一已经打通，并不等于方案二只是换一个指针。Zeus PE 直连 Weight LDG；开放任意 Fused UScale placement 会改变地址来源、依赖关系和资源生命周期，也可能改变 DRAM row/cache locality。方案二必须作为独立能力设计与验证，不能由本次方案一的结果外推。

当前实现边界

01 · BLOCK

weight 按 BLOCK_K 划分

每个 block 是一块 weight，并和同编号的 Fused UScale 组成 combined unit。

02 · PLACEMENT

Fused UScale 固定紧跟 weight

Original UScale 可以独立连续放置；当前不接受 Fused UScale 任意 placement。

03 · OWNERSHIP

buffer ownership 由调用方负责

双缓冲、并发 slot 与 graph 生命周期属于 torch_zeus/operator 层契约。
